# Mod Orchestrator

Desktop mod manager (Go + Wails v2 + React). The specification lives in
`mod-orchestrator-spec-v2/` and the design system in `dettmann-ui/`, both versioned in this
repository (the library build, `node_modules/` and `dist/`, is not versioned; see D052).

Status: **V1.0 in preparation** (spec phases F0–F15 implemented; the first public release depends on steps 4–7 of `plano-de-publicacao.md`). Changes per version: [CHANGELOG.md](CHANGELOG.md).

## Installation

1. Download `ModOrchestrator-amd64-installer.exe` from [Releases](https://github.com/LeonardoDett/ModOrchestrator/releases) and, if you want, check its hash against the release's `SHA256SUMS`.
2. The installer is **per user** (`%LOCALAPPDATA%\Programs\ModOrchestrator`) and **does not ask for administrator rights**. It requires Windows 10/11 x64; WebView2 is installed if missing. A portable `.zip` is also available.
3. Step by step until you play: [Getting started](docs/getting-started.md) ([Português](docs/primeiros-passos.md)).

**SmartScreen warning ("Windows protected your PC").** It appears for executables that are unsigned or have no reputation yet. Signing will be done by the SignPath Foundation, from the GitHub Actions build, with manual approval of each release (D077); until the project is approved, releases ship unsigned and the warning appears. Under "More info", signed releases show the publisher "SignPath Foundation". Pull request code never reaches the signing pipeline, and every published installer comes with `SHA256SUMS`.

**Updates.** Off by default (the app does not use the network). In Settings › Application › Updates you turn checking on and pick the channel (stable or beta); the installer only runs after it is checked against the release's hash and signature.

**Uninstalling** keeps your data (`%APPDATA%\ModOrchestrator`) unless you tick the option, and never deletes mods, staging or game folders.

## Layout

```
main.go                      Wails entry point
internal/
  core/domain/               pure entities and invariants
  core/application/          use cases + ports (operations, settings)
  infrastructure/            sqlite, eventbus, logging (technical log), system, appdata
  adapters/                  one adapter per game (only place with game-specific facts)
  bridge/                    UI <-> core transport (DTOs, bindings, events)
  bootstrap/                 composition root
  architecture_test.go       enforces the dependency rule between layers
sdk/                         contract that game adapters import
frontend/
  src/bridge/                typed backend client (Wails or offline), coded errors
  src/i18n/                  en/pt-BR catalogs (all UI text comes from here)
  src/shell/                 title bar, sidebar, top bar, palette, shortcuts
  src/features/              domain compositions built from library pieces
  src/pages/                 screens
  wailsjs/                   bindings generated by Wails (do not edit)
```

Structural decisions: `mod-orchestrator-spec-v2/docs-ia/decisoes.md` (D017–D023; F2: D053–D056; F3: D057–D061).

## Development

Prerequisites: Go 1.27+, Node 24+, Wails CLI v2, WebView2 (Windows).

1. Build the dettmann-ui used by `frontend/` (v2, D095/D107; once, and after every change to it):

   ```bash
   cd dettmann-ui && npm install && npm run build
   ```

   The build emits JS, CSS and `.d.ts` (the types step runs with an 8 GB heap). `npm run theme`
   checks contrast and the tone contract of the themes.

2. Run the app in dev mode:

   ```bash
   wails dev
   ```

3. Tests and build:

   ```bash
   go vet ./... && go test ./...
   ```

   ```bash
   npm --prefix frontend run typecheck && npm --prefix frontend test
   ```

   ```bash
   wails build
   ```

4. Installer (needs NSIS on PATH): `wails build -nsis` produces `build/bin/ModOrchestrator-amd64-installer.exe` from `build/windows/installer/project.nsi`. Releases only come out of the `release.yml` workflow (tag `v*`), never from someone's machine; checks in `go run ./tools/release`.

Application data: `%APPDATA%\ModOrchestrator\state.db`; technical log in `%APPDATA%\ModOrchestrator\logs`. To isolate it (dev/tests),
set `MODORCHESTRATOR_DATA_DIR`.
