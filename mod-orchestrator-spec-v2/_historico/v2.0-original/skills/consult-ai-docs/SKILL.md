# Skill — consult-ai-docs

## Objetivo

Reduzir custo de contexto e impedir decisões contraditórias.

## Quando usar

Antes de qualquer implementação, refactor arquitetural ou mudança de UX que altere fluxo.

## Procedimento

1. Identificar a fase.
2. Ler manifesto.
3. Ler decisões e anti-patterns.
4. Ler apenas os core/UI docs relacionados.
5. Buscar referências Vortex somente para comportamento correspondente.
6. Identificar fonte de verdade e invariantes.
7. Produzir um resumo interno de restrições antes de alterar código.

## Não fazer

Não tratar uma implementação anterior como autoridade superior aos documentos.
